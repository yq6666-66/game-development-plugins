## 蒸馏后保留的核心

1. 从当前问题选择最少方法，保持原工程、真实版本与冻结事实；不按宣传数量安装工具。
2. 先规定一个可证伪目标及范围外，正常路径加一个中断/反例；未知规则不自行编造。
3. 资产有用途、版本、尺度/方向、材质/动作/许可与运行消费者的合同；导出成功不是交付成功。
4. 展示读取权威状态；配置、运行数据、存档分离；终局、重开、取消和资源回收都要可验证。
5. 读实际断言和执行数量；0测试、0退出、文件存在、过期截图都不构成PASS。
6. 固定机位/质量/版本做画面对照，正常输入另验；编辑器、打包Player、真机、离线视频互不替代。
7. 性能先定瓶颈与可比测量条件，区分冷/暖态、平均/尖峰、CPU/GPU/存活内存；没数据不报0成本。
8. 失败存档不覆盖为新档；超时作业先对账，避免非幂等重试或重复计费。
9. 已有FAIL不能因风险接受、隔离测试或改baseline变PASS；证据随着相关依赖变动过期。
10. 每次最小单元完成即停；上游自动生成、部署、收费、安装和无限修复不是授权。

## 明确过滤的内容

- 上游固定默认引擎、重写工程、FPS武器模板、统一数值/帧率/面数及强制多平台。
- 错误优化泛化（如Vector3运算必分配）、逐帧订阅、重复死亡、未复位对象池等示例缺陷。
- 部分存档样例忽略失败、错误数据归零、未来字段丢弃等危险捷径。
- 用调试朝向/无敌/自动瞄准录像证明普通玩家体验；逐帧60fps证明实时60fps。
- 默认轴转换、合槽、改origin、挪碰撞几何，与冻结仓库布局/8材质槽冲突的做法。
- 根开源许可覆盖所有模型与输出的误解；外部凭据存在即认为收费/上传获准。

## 本次验证与未验证

PASS：两项技能结构校验、相对链接检查、独立场景任务推演（资产导入/证据分层；重开监听/测试可信度）。这些是技能文档验证，不是游戏运行验收。

未验证：上游脚本/插件、引擎或演示运行、实际游戏玩法、真机性能、商业输出许可完整链、Saltline与黄铜之心原件。

本分支仅供审阅与下次优化规划，不合并、不自动应用到游戏。后续先核真实文件和当前状态，再由用户放行一个最小可验证单元。
