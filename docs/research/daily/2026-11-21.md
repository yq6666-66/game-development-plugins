## 1. 同帧展示与同源证据不是一回事

**来源。** Jihai Zhang 等，[Matrix-Game 4.0 项目页 Results](https://matrix-game-v4-0.github.io/page/?lang=en#results)，读方法、结果与长玩说明文字；[预印本](https://arxiv.org/abs/2610.27999)，2026-10-20，仅读摘要。SkyworkAI 固定提交 a10eee250b2c007e855e5e915e28137bfb3c1c99（2026-10-28）：读 [4.0 README](https://github.com/SkyworkAI/Matrix-Game/blob/a10eee250b2c007e855e5e915e28137bfb3c1c99/Matrix-Game-4/README.md)、[录制/离线说明](https://github.com/SkyworkAI/Matrix-Game/blob/a10eee250b2c007e855e5e915e28137bfb3c1c99/Matrix-Game-4/docs/offline.md)及 [finalizer](https://github.com/SkyworkAI/Matrix-Game/blob/a10eee250b2c007e855e5e915e28137bfb3c1c99/Matrix-Game-4/game/tools/finalize-demo.py) 的校验和合成逻辑。读取 11-21；未运行上游脚本、检查完整源码或复现 Issue。三种材料为同一项目，不独立互证。

**事实与推导。** 作者用同一成片的左右半帧展示代理和生成画面；离线文档将 HUD、音频、输入、事件和干净画面分轨，finalizer 检查各自的帧数、时间戳、音频区间和若干事件关联，再合成。共享播放器时基可防播放进度漂移，却不自动保证进入合成前的内容未错位：正确的显示时间戳仍可承载上一帧画面。这是对证据边界的推断，不是声称发现上游缺陷。作者的离线模拟按键提前量不是测量延迟；其模型吞吐也不是浏览器展示帧率或端到端响应。

**便携做法。** 当现有视觉试验需要逐时刻比较动态遮挡或 HUD 跟随时，记录测试版本、输入轨迹、配对键（共同源帧/事件与可解释的时间坐标）和允许变更。不同运行的局部帧号不能直接认为共享同一身份；没有共同标识时只报告可确认的语义锚点与覆盖，不伪造逐帧精度。先查缺帧、重复与索引，再用一个移动事件或可见标记核对内容；合成后仍保留原证据和标识。参数只取项目约定，不照搬固定帧率、模拟倍速、编码器或阈值。

**最小检验。** 先取正常同源序列，再让一轨内容延迟一帧但保留总帧数和时间戳，要求在首个错配显示失败。仅对实验用元数据做本地反例，[记录见此](../../validation/daily-2026-11-21.md)；真实视频、音像同步、输入到显示与 GPU 均未测。即便正确配对，也不能证明不同渲染版本有同等画质或相同手感。成本是源身份记录、储存与事件锚点维护；普通静帧诊断不需要新增录制系统。可在实际检出后考虑放进视觉证据参考，不采用上游渲染器。README 声明项目代码 Apache-2.0，权重、素材有各自声明；未逐项审计其许可，未下载或移植。

## 2. 播报状态而不劫持玩家操作

**来源。** Microsoft Game Dev / Xbox，[XAG 106 屏幕朗读](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/106)，页面更新 2026-11-13，读朗读时机、内容与实现指导相关文本及示例说明；未看/听视频。W3C Accessibility Guidelines Working Group，[WCAG 2.1 对 4.1.3 的理解指南](https://www.w3.org/WAI/WCAG21/Understanding/status-messages)，页面更新 2026-10-04，读益处、示例、技巧和定义的相关文本。均 11-21 读取，动态页面，无固定 Git 提交；后者是 Web 的解释指南，不是原生游戏认证要求。

**来源机制。** XAG 区分焦点、上下文转换和通知，支持快速换焦时不让旧朗读阻塞新项；W3C 讨论无需转移焦点而可由辅助技术呈现的状态更新。它特别指出仅更新数字可能丢失语义，忙碌文本移除也未必告知结束。两者支持分开处理，不表示 Web 机制可直接照搬原生 HUD，也不保证所有设备朗读相同。

**候选做法。** 项目已支持朗读时，为一个玩家任务写事件、状态真源、焦点预期、完整可读语义、是否允许积压/中断和恢复路径。功能结果、模态上下文切换、主动浏览目标分别走适当机制；默认不要为报一个非模态结果而移动焦点，也不让场景离开前的低优先播报阻塞当前控制。区分应用发出状态、辅助技术接收和玩家实际听到三层证据；不把一条输出日志当朗读通过。不依赖固定朗读节奏或暂停全部音频，不因此启用新服务。

**最小验证设计。** 用项目支持的屏幕阅读器/游戏内朗读与正常输入完成一次耗时操作：途中移动焦点、快速触发低优先变化、结束时去掉忙碌状态；检查最终可操作状态有完整语义，输入目标未被非模态通知抢走。另比较真正模态错误、仅显示数字变化和低优先提示连发是否具有不同预期。现阶段只做静态情境推演，未执行任何辅助技术。语速、语言、优先级、与声音线索的冲突及设备矩阵有额外成本；可在已授权界面得到真实语音和操作证据后再升入 UI Skill，勿当全面无障碍结论。
