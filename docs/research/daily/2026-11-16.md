## 主题 3：编辑器资源不等于交付资源

来源：Godot contributors，godot-docs 提交 `2c6cc131ac13f14443e052ccc91393986f37ae26`，提交时间 2026-11-14T19:57:30Z；读取 2026-11-16。全文读 Import process 和 Runtime file loading and saving 文本，未查看配图；不是特定稳定引擎兼容承诺。固定链接与便携流程见[运行资源合同](../../../skills/game-build-delivery/references/runtime-resource-contract.md)。

- 问题：开发机可读源文件，但交付后实际只剩导入表示；模型本体加载成功却遗漏相对纹理。
- 来源事实：导入资源经映射读取、原样文件访问及外部文件加载属于不同路径；glTF 缓冲区缺少文件目录上下文，需要外部资源根。
- 原创综合：先分类资源并记录“来源→导入→包内表示→加载器→依赖”，再在脱离源工程的交付副本验证。不要靠全量复制源资产或换成原样文件掩盖路径错误。
- 使用条件：现有打包/加载任务，实际引擎版本、导出模板、样本资源与目标环境已获准；外部内容未在范围内则跳过。不新加模组、网络下载或安装软件。
- 最小验证建议：一个导入资源和必要原样文件，交付目录正常操作；若有外部模型，比较文件/缓冲区相对依赖；隔离副本缺一依赖，应出现合同规定的错误/降级。以上均未执行引擎。
- 局限：解码安全、巨大资源性能、平台文件路径及导出变体另需验证。本次未以 Issue 证明引擎缺陷。
- 落地：构建 Skill 目录内双语参考与中英入口。相对原有“核对导出内容”增加资源类别/加载路径/依赖诊断，判断收益应看实际交付坏样本是否被检出。

## 主题 2：重绑定恢复要验证身份与提交边界

- 来源 Unity Technologies/InputSystem 开发快照 `3ec61dddad2cffb6badc9092eb8b39152c5cf3ef`（2026-11-12T09:40:02Z，包清单1.20.2但 CHANGELOG 为 Unreleased）；官方1.14.2版本文档作机制对照。完整读取样例及局部保存/恢复实现，具体行范围和固定链接见[参考](../../../skills/game-playloop-validation/references/rebinding-recovery.md)。公开库维护模式，不称所有Unity版本最新实现。Issue搜索未取得主体，不作证据。
- 问题：改键成功却无法跨重启/资产变化恢复，设备中断被误作松开提交。
- 来源事实：override单独持久化；恢复按绑定ID匹配；默认清除现有覆盖与随后解析是不同阶段；设备ID非跨会话身份。组合取消是否整组回滚必须明确。
- 推断：加载无崩溃可能仍部分失败；应用前快照与恢复合同避免静默丢失。不能据此宣称作者样例在所有路径已失败。
- 条件：当前项目已支持重绑/设备路径、实际action资产与配置；无此功能跳过。Unity API必须核实际版本。
- 最小验证建议：改键保存重启；旧ID/坏JSON；组合第一部件完成后取消；按住拔设备再重连。检查配置、实际动作、提示及上下文恢复，不强制全部Enable或暂停。未运行引擎/设备。
- 局限：迁移与设备矩阵有成本；输入包公开快照不替代锁定版本，旧文档不证明新版本全部行为。
- 落地：玩法 Skill 中英专项与路由；新增持久化身份、失败恢复及取消边界，补充既有输入/UI隔离，不新增近似技能。Unity Companion License 等上游条款不被本仓库MIT改变，无源码复用。
