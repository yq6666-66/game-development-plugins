## 1. 最后画面是 B，不能证明过期的 A 没提交

**来源。** Godot contributors，Godot 4.5.1-stable f62fdbde15035c5576dad93e586201f4d41ef0cb：[SceneTree 切换实现](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/scene/main/scene_tree.cpp#L1534-L1592)、[SceneTree XML](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/doc/classes/SceneTree.xml)、[ResourceLoader XML](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/doc/classes/ResourceLoader.xml) 及 [ResourceLoader 实现](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/core/io/resource_loader.cpp)。读 API 和实现相关段落，不把生成文档的概括当源码行号。4.5.1 只查源码；本地已有 4.7.2.stable.official.ed1daf0bf，另做 Linux 无头实验，不能代作 4.5.1 实测。

**新证据。** 4.5.1 中切换 API 先尝试实例化，成功后安排实际入树；后续成功调用可替换尚未提交的 pending 场景。信号在实际入树之后，无应用意图参数。4.7.2 独立两场景小样中，直接同一帧调用 A、B，两次返回 OK，最后只得到一次新的 scene_changed，且 current_scene 是 B；这在外观上与正确阻止旧提交的情况可能相同。只盯最后场景/信号会漏报已经发出的旧调用。详见[实际记录](../../validation/daily-2026-11-24.md)。

**最小便携流程。** 对已获准的异步切换，从不会随旧场景销毁的观察者记录：引擎加载请求返回码和终态、取得的资源类型、应用意图 ID、提交次数/返回码、入树信号与当前实例、独立就绪条件及一次正常操作。异步加载先等已加载终态再取资源；引擎就绪不是业务就绪。路径相同也要比意图 ID（A→B→A 首次 A 仍旧）。本地小样手工延迟的是完成结果的应用交付，不是模拟真实慢盘或线程竞态；不证明引擎取消、同路径多并发加载、重入式 _ready 或玩家输入。只补现有 W47 加载参考的检测分辨率，不新增项目设施。成本是少量可观察点与两场景夹具；其他平台和已锁定版本应复测。

## 2. 音效已触发，不代表关键提示占到了可听声部

**来源。** Godot contributors [4.5.1 AudioStreamPlayer XML](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/doc/classes/AudioStreamPlayer.xml) 的 max_polyphony 段；Unity Technologies Unity 6.0（6000.0）[AudioSource.priority](https://docs.unity3d.com/ja/current/ScriptReference/AudioSource-priority.html) 与 [isVirtual](https://docs.unity3d.com/jp/current/ScriptReference/AudioSource-isVirtual.html) 语义与平台说明。前者固定提交，后者所读页标注版本但 URL 会更新，无固定源码提交；均读相关正文，未核发布日期或运行音频。

**机制与流程。** Godot 此节点的局部并播满后，新播放可截断最早声部。Unity 所述虚拟化可继续跟踪播放状态但使声部无声，涉及全局预算、优先级和音量；isVirtual 为所指 AudioSource 的整体状态，不能鉴别其中某条 one-shot。两套机制不是同一个参数。对已有关键提示，分别查动作是否发出、实际播放路径/并发限制、最终混音中是否仍可辨；既有替代视觉/触觉通道亦须保留。不要把全局增加声部或一律最高优先级当默认修复。

**最小检验。** 单独一次提示作为正对照，保持状态和输出路径不变，再在代表性负载下触发真正竞争的局部或全局声部；同时记引擎状态和实际输出，不让触发日志冒充玩家听到。若仅错过关键声音，比较取消冗余声部或按项目既有优先级隔离，不抬高全局响度遮掩。静态情境，未测听觉。成本是真实音频链、竞争负载、设备矩阵；补 11-14 声音信息覆盖的“并发下能否到达”一层，不改现有玩法参考。

## 3. KTX2 是兼容性分支，不是所有客户端都会采用同一纹理

**来源。** Khronos Group contributors [KHR_texture_basisu](https://github.com/KhronosGroup/glTF/blob/70b5e4101725950fb8f3f94dd72c37e758ce5daf/extensions/2.0/Khronos/KHR_texture_basisu/README.md)，批准标准基于 glTF 2.0，固定提交 70b5e4101725950fb8f3f94dd72c37e758ce5daf（2023-08-28）。读 schema 更新、外部与嵌入双源例、无 fallback 的声明及 KTX2 运行说明；未核导入器源码、转码或 GPU。只作原创综合，未复制示例资产或代码。

**机制与流程。** 可选扩展可并列核心图片和扩展图片，不支持扩展的查看器使用核心图片；无核心备份时规范示例把扩展列入 used 和 required。区分“不支持扩展时按合同切核心图片”和“支持扩展但数据缺失/损坏”，后者不由该示例保证自动恢复。支持 KTX2 也不等于实际 GPU 使用某个压缩格式或占用一定降低。已有导入路径才测：记录纹理槽、扩展声明、加载器/构建及实际格式；同一资产对照两个实际支持范围和一个缺失源坏样本，验证走了哪个分支及必要外观。不得把默认纹理视为完整。若两个路径不可实测，记录未覆盖。与 11-23 的材质映射切换不同，本项是导入能力及图像来源决策；只作为构建/资源候选。未使用转码器、未生成二进制资产。成本包括双源包体、平台路径与首用解码/显存。
