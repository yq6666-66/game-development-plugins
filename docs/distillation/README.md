# 从资料到可复用 Skill

[English](README.en.md) · [首页](../../README.md)

本教程面向游戏开发学习者与贡献者。欢迎复用本仓库的原创 MIT 模板，继续蒸馏；不要求使用特定 Agent、引擎或生成服务。

## 一次最小蒸馏

1. **从问题选题。** 例如“重开后重复响应”，而不是“今天收集三个链接”。先检索现有技能、研究记录和未合并分支。
2. **读主体与证据。** 记录原作者、链接、日期、版本/提交及具体读取部分。读字幕不等于看过画面，读代码不等于运行；获取不到主体只算线索。
3. **抽取方法。** 写问题、机制、步骤、取舍、前提、输入输出、失败条件与替代路线，不照抄宣传或把案例数值设为默认。
4. **构造最小检验。** 在已授权环境比较正常路径与反例。无法运行时写“未运行”，以情境推演检查错误假设，但不冒充游戏验证。
5. **选择落点。** 通用判断放 `SKILL.md`，细则放该 Skill 自己的 `references/`，未成熟观点与研究过程放 `docs/`。新增 Skill 先证明其独立职责。
6. **提交可审阅差异。** 保留可恢复基线，检查来源、许可、链接和相关测试；改变流程时追加情境推演。不得因研究来源建议而自动安装、付费或部署。

示例：某教程建议“重开前清空所有状态”。蒸馏时先问哪些状态属于单局、哪些属于设置或持久进度。比较重开前后单局计数与持久设置，检查监听是否重复订阅。结论是“按状态所有权定义重置边界”，而不是无条件清空所有数据。这是教学推演，非新运行证据。

## 每日与每周

每日目标约三个有价值主题，质量不足可减少。使用[研究与候选模板](templates.md)，记录来源读取与运行状态，推送 `distill/YYYY-MM-DD`。同日重跑先补齐原分支，避免重复。

每周一汇总上一自然周，使用被汇总周的 ISO 周编号 `weekly/YYYY-Www`。核对每日提交、去重、整合有依据的改进，形成 1–3 个带反例与最小验证方法的综合判断。证据不足可减少。周报不自动进入正式 Skill；周分支不自动合并或发布。

北京时间维护约定：每天 09:00 研究，每周一 10:00 整合。本文不安装调度器，也不证明任何定时运行已成功；连续性以仓库研究记录和实际提交为准。

## 复用与贡献

原创模板遵循 [MIT](../../LICENSE)。引用第三方资料保留链接、作者与版本，单独检查代码、素材和模型许可，不能用本仓库许可覆盖上游条款。投稿应给出具体问题、改动理由、来源、验证与未覆盖风险。中文优先，英文对应文档同步更新；暂未同步需明确标记。
