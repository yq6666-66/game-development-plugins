# 测试与性能

[English](06-testing-performance.en.md) · [返回八类导航](../README.md)

## 何时使用

证据不足、回归遗漏、卡顿或资源增长；先说明要证明什么。

## 输入与交付

- 输入：版本、环境、重现路径、目标指标及已知反例；预算未知时明确标记。
- 交付：测试矩阵、结果与失败证据、测量范围及未验证项。

## 两条起步路径

- **从零开发：**为最小循环定义可观察断言与一个失败样本，不先搭全套平台。
- **接手项目：**先复现并留基线；选与改动相关的路径和中断，不把旧成绩当新版本通过。

## 当前可用入口

[game-playloop-validation](../../../skills/game-playloop-validation/SKILL.md)。阅读真实入口及本次需要的目录内参考，不一次加载全部资料。

完整测试框架、跨设备自动化和性能分析器尚未提供；画面问题可转画面 Skill。

## 最小检查

区分包校验、任务推演、宿主加载、引擎运行和目标设备测试；性能比较固定条件，分别记录 CPU/GPU/端到端可得证据。

## 工具选择与下一步交接

通过[资源选择](../../../skills/game-resource-selection/SKILL.md)和[推荐卡](../../resources/README.md)按项目需求选择。分类不是引擎/框架白名单，也不是产品背书；不适用的系统不要新增。

向下一分类交接目标、基线、改动范围、证据和未决事项。本页是导航文档，不是新增可安装 Skill；正式 Skill 仍可独立复制使用。
