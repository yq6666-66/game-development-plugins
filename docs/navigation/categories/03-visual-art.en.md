# Visuals & art

[中文](03-visual-art.md) · [All categories](../README.en.md)

## When to use

Style inconsistency, asset import differences, material/lighting faults or visual readability issues.

## Inputs and output

- Inputs: References, actual assets, units/axes, rendering configuration, viewpoints and devices.
- Output: Visual target, small sample, controlled comparisons and runtime risk record.

## Starting routes

- **New project:** Establish a representative area and material/model samples before adding content and effects.
- **Existing project:** Preserve originals and check import contracts; isolate asset, material, lighting and runtime causes.

## Available entry

[game-visual-iteration](../../../skills/game-visual-iteration/SKILL.md). Read the actual entry and only its needed local references.

There are no dedicated full character, rigging, animation-authoring or asset-production Skills.

## Smallest check

Compare the same viewpoint and observation conditions, changing only the experiment variable; offline renders are not runtime evidence, and art acceptance is not gameplay acceptance.
