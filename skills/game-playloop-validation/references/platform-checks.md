# 平台检查

只读与当前任务有关的一节。以下是诊断方法，不是要求更换技术栈。

## Unity

- 先确认实际 Unity 版本、当前场景、输入配置与已有动作资产，复用已有输入系统；不要同时创建新旧两套。
- 修改脚本、Prefab、场景或资源前检查引用关系，保留已有 .meta/GUID；不得用重新导入重建引用来掩盖问题。
- 区分菜单与游戏动作上下文；验证按住键时开菜单、失焦再返回、暂停时按输入、重启后的输入状态。
- 编译通过只证明编译；PlayMode、独立开发 Player、目标设备分别留证据。性能结论不能仅来自 Editor。
- 先核实际启用的渲染/质量配置，不把资产“存在”当作启用。

## 浏览器

- 区分输入、规则状态、渲染与平台事件；已有框架优先，不为套分层而重写工程。
- 移动与计时不依赖固定渲染帧数。验证帧率变化和恢复后的大时间间隔，避免跳跃位移；时间处理以游戏实际规则为准。
- 检查 pointercancel、lostpointercapture、blur、visibilitychange 等相关事件是否清除持续输入。
- 鼠标锁定失败应可理解地提示；触控路径不依赖鼠标锁定。
- 若使用音频或 WebGL，验证首次用户手势后的音频启动、资源加载错误和 context lost 的恢复/失败提示。
- 游戏逻辑向 UI 提供状态，UI 发出意图；不要让界面组件直接制造未校验的胜负或资源变化。
