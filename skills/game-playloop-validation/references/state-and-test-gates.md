# 状态与测试的可信门槛

遇到重开残留、重复事件、异步问题、导航/碰撞、存档或“测试都绿但游戏坏了”时按需读取。只实施当前获准的系统，不因这里列出存档、AI或发布检查就新增功能。

## 1. 可证伪任务卡

沿用现有文档位置，写最短能执行的内容：

> 基线/版本与事实来源；玩家遇到的现象；机制→行为→预期体验；一个主假设及竞争解释；允许改动与保护项；Given/When/Then正常路径；一个中断/反例；要观察的状态前后值/提示；证明方法、回退与停止条件。

先分类：没理解规则、操作失败、状态错误、数值失衡、表现反馈、性能。崩溃、卡死不归“手感”。构建错误先找最早可行动阻塞，别追连锁报错。玩家观察、自述、遥测、源码分析与作者猜测分别记录。未知规则回查规划，不能为完成模板编造数值。

## 2. 生命周期与单写入者

对本单元列出状态/资源、唯一权威写入者、进入、退出、暂停、重开、销毁的处理。动画、UI、音频读取已成立的动作结果；导航、物理、根运动不能争写同一变换。配置、每实例运行状态和持久化状态分离。绘制只展示，不扣资源、推进AI或发音效；鼠标位移与摇杆速率使用各自时间契约。

最小回归选择正常循环加一个中断，必要时连续两局：
- 扣资源、授予结果与状态切换应全成功或全失败；条件改变、容器满或重复触发不能只扣不发，表现读取已提交结果。
- 终局与奖励只结算一次；同帧冲突事件遵循已有规则，不凭实现顺序偷偷决定胜负。
- 输入按下/持有/释放/取消、buffer消费及菜单上下文明确；失焦、死亡、重开不残留持续操作。
- 订阅、计时器、协程、异步请求、音频与动画在退出时释放或取消；晚到回调不能改已销毁或新一局对象。重复进入后监听/对象数不增长。
- 池对象借出、归还均重置速度、状态、计时、监听、可见性等实际字段；处理重复归还与容量，不以SetActive当完整复位。
- 连续Play/重开查静态数据与内存配置污染；只比磁盘哈希发现不了内存脏状态。
- 反馈叠加有所有者和恢复值；结束后不强行把timeScale设1覆盖暂停。hit-stop/击退如会改变规则或时序，应按玩法变更另定范围，不冒充纯美化。

## 3. 空间与AI只验证真实路径

从感知→决策→路径→转向→动画逐层定位。NavMesh资产存在/烘焙完成不代表已加载、agent在网格上、目标可达或路径完整。记录不可达、部分路径、丢失目标、中断和重复进入的结果；行为reset幂等，不清掉应保留的冷却。

碰撞使用现有控制器及2D/3D物理体系；按实际角色尺寸检查门角、障碍物、斜向与薄墙。边界通过不能覆盖所有物件碰撞。不要泛化地把所有Update移动改FixedUpdate，应先判断Rigidbody、CharacterController或自定义控制器的运动所有权。

关卡可达图若涉及钥匙、资源或单向门，要包含可获得状态与消耗；连通不等于顺序可解。算法检查和玩家正常输入各自出证据，不瞬移、Warp或挪布局消除失败。程序化任务另记seed/生成器版本、跨进程重现、有限重试与失败样本；不为手工地图新增生成器。

## 4. 仅已有存档任务时启用

先查实际格式、历史样本、版本与稳定ID。读取/解析→逐版本迁移→校验→一次性应用；失败不得半更新运行状态。未来版本应明确拒绝，损坏主档按约定回退并提示。读失败不等于新档，不能生成默认值覆盖原档，也不自动归零或丢弃未知字段。保存失败/超时也可能已经写入，重试前核实，尤其非幂等操作。保存纯数据，不加载可执行对象；本地存档不能作线上经济权威。

在隔离测试副本验证：往返、旧版本迁移、更新版本拒绝、截断/非法字段、写失败、备份回退及完全退出再启动。检查每次写入/替换/备份结果；temp+rename不是跨平台断电零丢失保证。不要覆盖用户唯一存档或自动删除损坏证据。自动存档在一致状态边界，不能覆盖手动槽。

## 5. 测试本身必须可信

- 记录发现/计划/实际执行/通过/失败/跳过数量，读取断言及结果文件。空测试表、零执行、缺预算、缺文件均不能写100%或0问题。
- 关键检查选一个隔离的负向控制证明它确实会失败，例如错误期望或损坏副本；不修改生产数据来制造故障。测试fixture不能偷偷补本游戏缺失输入配置，再声称实际游戏通过。
- 退出码、日志、测试报告、图像和正常输入各查适用项。进程0退出不代表没有引擎错误；日志错误需区分预期故障注入和意外失败。
- 编译、纯规则、虚拟输入、编辑器、打包Player、目标设备分别报告。使用实际构建产物在干净路径冷启动，不能在项目源目录启动另一份代码代替产物验收。
- 固定seed/轨迹与截图回归是补充。差异先判预期/回归，不自动更新baseline；截图不能证明碰撞、音画同步、重开或体感。
- 验收绑定版本、相关依赖及方法。改动后找消费者（UI、小地图、测试、导入设置等），记录N项中审M项；无追踪不能说0影响。风险接受不等于PASS。

UI先按玩家决策列常驻/情境/按需信息，再布局；游戏状态由系统拥有，UI可以保留本地焦点和展开等交互表现状态。检查隐藏层拦输入、快速开关、空/加载/错误/禁用和重生重复绑定。

偶发失败记录当前build、环境、seed和运行顺序，区分累计分配和存活内存；不能靠隔离失败测试、更新基线或增加重试求绿，已有FAIL不被BLOCKED冲淡。不支持的平台列范围外，支持但未测列未验证。

Bug改完先标“待复验”，复跑原复现和邻接路径后才关。独立审查须有可定位文件与失败条件，不把同一轮角色扮演称作多人验收。最终只对实际执行内容下结论，未覆盖保留BLOCKED/未验证。
