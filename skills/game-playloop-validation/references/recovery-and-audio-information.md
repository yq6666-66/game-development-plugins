# 恢复关系与声音信息检查

[English](recovery-and-audio-information.en.md)。在现有存档或可访问性任务触发时使用；不自动新增系统、不绑定引擎。与 [状态与测试门槛](state-and-test-gates.md) 配合，仅补充关系恢复和信息覆盖。

## 来源事实与本页推断

2026-11-14 阅读 [Godot 4.4 Saving games](https://docs.godotengine.org/en/4.4/tutorials/io/saving_games.html) 的序列化、读写、注意事项与格式限制。其示例假设持久化对象不互相嵌套；嵌套时需要先恢复父级，并解决路径可能失效的问题。它不是完整生产存档方案。

同日阅读 Microsoft [XAG 104](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/104) 的目标、适用问题与实施准则：对白字幕和涵盖重要非对白声音的信息不同，重要声音可能需要视觉替代；字幕设置应在相关内容出现前可用。本轮没有观看链接视频、检查图片像素或运行示例。下列测试方法是本项目的综合建议，不是来源已验证结果或平台认证要求。

## A. 验证恢复的是关系，而不只是字段

**适用：**读档后物件丢失、附着错误、重复生成或 HUD 正确但交互错位。输入为原存档副本、版本、对象身份与关系约定；输出为恢复前后对应表和失败证据。

1. 分别记录稳定身份、父子/引用关系、运行字段；不要把显示名、数组顺序或临时场景路径未经验证就当永久身份。
2. 按现有架构检查恢复阶段：数据校验、实例建立、关系连接、状态应用、恢复运行。依赖不存在时按项目约定等待、拒绝或回退，不能静默连到同名对象。关系有环时不能简单要求“所有父级先完成”，需要项目可支持的分阶段解引用策略。
3. 隔离副本选一个带子对象或外部引用的样本，保存后改变运行时创建顺序，再正常读档。比对对象身份、关系、数量及一次真实交互，不能只看坐标或 JSON 往返。
4. 追加一个缺引用/重复身份样本，检查明确报错及旧世界保留/回退策略。恢复失败不是新游戏，不覆盖唯一存档；单个标量原型无需为了此表搭复杂对象图。

## B. 验证信息覆盖，而不只是字幕开关

**适用：**玩家在静音或听觉受限条件下漏掉目标、危险或操作结果。输入为任务中已存在的音频事件与 UI；输出为“事件→决策信息→等价通道→实测结果”表。

1. 从一条实际路径找关键事件，区分对白、非对白和装饰声音。只记录音频实际携带且玩家有权获知的信息，不能为了提示额外泄露隐藏敌人的精确位置。
2. 关闭声音，用正常输入验证是否仍可判断下一步。已有清楚的视觉反馈可复用，不必为每个声音叠加文字。
3. 在实际支持的尺寸、语言及设置下，检查可读性、遮挡、事件重叠、暂停/恢复与重开后的过期提示；设置页预览不能代替游玩时检查。显示时长、方向与信息粒度按项目验证，不照抄别的游戏数值。
4. 保留一个反例：字幕开着但关键非对白信息没有替代；如果仍漏掉决策，就不能因“有字幕”判通过。此小样本不代表全面可访问性认证。

## 证据边界

记录版本、设备/输入、实际操作、事件与可见结果。文档阅读、任务推演、宿主加载、实际游戏和真实用户测试分别报告。没有相应存档或音频系统时标不适用；有系统但不能运行时标未验证。本文不提供可执行代码、资产或第三方许可再授权。
