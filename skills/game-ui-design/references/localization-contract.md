# 本地化语义与导航合同

[English](localization-contract.en.md)。仅用于项目已声明的语言与输入方式；不增加语言、字体依赖或翻译服务。已有字体/布局检查之外，本卡检查“什么被翻译、按什么顺序操作、交付时仍是否成立”。

## 小步流程

1. 给一个实际屏幕的字符串标出类别：产品消息、用户原文、结构化标识。消息按语义上下文查找；玩家名碰巧等于消息键也应保持原文。文件路径、数字和自然语言不要不加区分地翻译或镜像。
2. 把测试分成两层：伪本地化用于发现未接入翻译的文案和长度压力；真实支持语言用于检查字形、塑形、方向与语义。前者通过不能替后者通过。只记录实际选用的样本，不声称覆盖整个语言。
3. 切换语言后，检查布局和操作两条路径。分别走方向键/D-pad邻接与Tab顺序（仅在支持时）；文字/容器镜像不自动证明导航合理。焦点项隐藏后用已约定的后备项，取消应返回合法入口。不让测试脚本直接设焦点掩盖玩家无法进入的路径。
4. 在获准的独立交付样本检查相同文本。需要字典分词数据的语言，核对实际导出设置和版本；编辑器成功不替代交付结果。复原临时测试语言设置，保留原有玩家偏好和默认语言。

## 最小记录与反例

记录语言、文本类别、输入路径、实际字体/布局配置、观察结果与未覆盖项。合成反例：用户取名为一个翻译键，切语言后名字改变；加长拉丁字符不溢出，但真实中文缺字；RTL布局正确而D-pad跳到视觉上错误的按钮。这些能拒绝笼统的“本地化通过”，不是本轮运行发现。不要为了通过检查把所有节点的自动翻译关闭或强制所有语言使用同一方向。
