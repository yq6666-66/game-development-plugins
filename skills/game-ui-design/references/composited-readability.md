# 合成画面的可读性证据

[English](composited-readability.en.md)。用于当前屏幕的重要信息，不将装饰或全部游戏画面纳入同一指标。

## 来源与取舍

Microsoft / Xbox，[XAG 102: Contrast](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)，页面更新 2026-11-13，读取 2026-11-18。完整正文与示例说明文字已读，未核示例图片像素或视频、未运行游戏。来源强调不同背景及最不利区域；数值要求区分元素类型、大小和模式，须按当前标准核对，不硬编码一个比值。无源码版本或实机通过声明。

## 原创验证卡

1. 写一条玩家信息链，例如看见目标、分辨状态、作出操作；确认信息源及保护项。
2. 用固定路线和 UI 状态选择亮、暗、纹理复杂的背景；仅在项目确有时覆盖闪光、叠层、转场。计划样本与实际覆盖分别计数。不要将未观察到的视觉状态当成已覆盖。
3. 对最终合成画面而非设计面板的色值检查最不利位置。记录元素、背景、透明度、显示/渲染配置、测量方法、适用标准与结果。半透明底板的原始颜色不是合成后的背景颜色。
4. 默认和已支持的自定义模式分别验证。底板、轮廓等改动不能挡住必要信息；禁用选项仍应表达原因，不把提高饱和度当作状态语义修复。
5. 正常输入完成信息链，分开报告测量结果、动态观察和用户理解证据。没有目标显示器、真实操作或用户研究时，明确未覆盖。

反例：夜景通过但天空背景失败；透明底板遇高亮效果失效；用户颜色覆盖导致两个状态难区分。先观察再判断，不认定这些故障必然存在。测量成本来自状态/背景组合，不要求穷举不相关场景。高对比不保证不遮挡或能及时理解；HDR、色调映射与缩放另按实际管线核查。本文件只提供原创流程与来源链接，不复制第三方素材。
