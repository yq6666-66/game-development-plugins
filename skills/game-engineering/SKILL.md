# 游戏工程搭建与架构演进

[English workflow](references/workflow.en.md)。输入是项目目标、平台、已选技术、实际文件/约束和允许的改动；输出是可解释的模块边界、最小实现或方案、启动方式与运行证据。可以单独复制此目录使用。

## 建立真实起点

新项目：先确认一条目标路径，例如进入场景、触发动作、展示结果、退出。选支撑这条路径的最小结构，未决定的引擎或规则不从教程强行继承；只做方案时不创建工程。

已有项目：核对入口、锁定版本、构建步骤、状态写入者和当前行为。先复现或标明阻塞，再确定可恢复改动边界；不因文件较大就换框架。缺失运行环境不妨碍输出静态分析，但不能宣称可运行。

## 用所有权决定边界

为本次状态记录：谁创建、谁能修改、谁读取、何时重置、谁释放。将规则状态与表现对象的职责区分，但按实际引擎保留必要耦合，不要求所有游戏重写为纯函数、ECS或全局单例。

选择一个接缝，说明请求、结果或事件、错误路径及生命周期。直接调用适合明确的请求/响应；事件适合通知已发生事实，但须明确顺序、订阅归属与清理。依赖从可观察的组装点提供，比组件遍历任意父级寻找服务更易替换；小原型不必引入依赖注入库。

对跨关卡持续对象，区分位置关系与销毁归属。挂在房间下的玩家是否应该随房间消失，必须由游戏规则决定，而非层级方便决定。需要时阅读[边界决策与样本](references/boundaries.md)。

## 在授权范围实现一条纵向路径

保留基线与原接口调用者，先完成输入→状态变化→表现→退出这一条切片，避免同时搬动无关模块。配置、资产标识、可序列化数据及运行对象按用途区分，不强制格式或目录名。优先复用已有运行依赖；确实缺少的依赖按明确任务授权及宿主规则处理，不因新工程尚无依赖而拒绝搭建。此 Skill 不自行授予安装、新服务、引擎升级或发布权限。

用真实入口编译/启动；检查一个正常流程和与改动有关的销毁、重载或取消流程。实例可重复创建时测试两个实例，避免静态共享状态意外串扰。发现隐藏调用者时缩小改动或修订方案，不以重试掩盖生命周期问题。

## 交付与停止条件

列改动文件、所有权/接口决定、保留/拒绝的替代、执行命令、实际结果及恢复方式。只有图与源码审阅时标静态；编译成功不是运行成功，单元测试也不覆盖场景装配。未能验证的目标平台、设备与外部依赖单列。范围发生实质变化先交回决策，不顺手扩建整套系统。
