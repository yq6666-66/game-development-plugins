# 游戏画面小步迭代

[English workflow](references/workflow.en.md)：目录内完整英文主流程；历史专项参考仍保留各自语言与证据范围。

将参考转成玩家可观察的改进目标，而不是复制美术或默认追加特效。适用于既有 2D/3D 项目，也可为用户明确授权的新原型建立小型视觉样板；不是整款游戏生成器。只读取本任务需要的参考。

## 1. 确定这次要证明什么

先判断本轮是方案、诊断还是实施请求。仅要求方案或诊断时，先给出分析与计划；写入副本、修改文件或运行引擎须在本轮授权范围内。

既有项目读取实际入口、版本、场景、资产和当前有效的渲染配置。区分已观察事实、提供者陈述与待验证假设。沿用项目的布局、风格、输入、预算及授权范围；相冲突的基线或必需输入缺失先列为阻塞。新原型尚无入口或资产不自动构成阻塞：在明确授权范围内提出并标注可撤销的样板假设，区分用户要求和建议，不把假设冒充既有决定。

用一句话写“玩家需要更容易看清什么”，注明对象、距离/尺寸、运行状态和不变项。参考分别说明借什么、不借什么。当前任务的停止点、允许变更与重试预算来自项目约定，不从来源案例继承。

## 2. 选择一个责任层

| 现象 | 先隔离的变量 | 常见误修 |
| --- | --- | --- |
| 轮廓、空间或方向不对 | 实际加载版本、几何、相机、缩放/朝向 | 先调灯光，或挪布局掩盖问题 |
| 不同资产像拼接 | 视觉规格、主要形状、配色和材质作用 | 为模仿参考更换整套风格 |
| 受光面平、暗部无信息 | 主光方向、补光、曝光及反射 | 叠 Bloom 或把所有表面照亮 |
| 材质不可信 | 贴图绑定、数据通道、色彩空间和局部使用痕迹 | 全表面噪声、将细小凹凸当积水 |
| 近看粗糙、远看难辨 | 实际观察距离的剪影、结构、边缘 | 先堆微细节或新增大量独立物体 |
| 加效果后更难玩或更慢 | UI/目标遮挡、当前生效的特效与性能瓶颈 | 同时打开所有效果后仅凭截图判优 |

选择少量有代表性的样本；视觉、材质、模型、HUD 和音频可分开实验，不要求每次建立完整样板场景。近景重点由游戏决定：单位剪影、落点、角色动作或交互道具，不默认等于枪械。

## 3. 小实验而非整包替换

先保存可回退基线，确定正常输入路径和必要观察点。每次改变一个可解释的因素，固定除本轮自变量之外的相关条件，例如机位、分辨率、质量或曝光；若测试曝光，就只改变曝光并保持其他条件一致。比较改善与代价，不以换角度、降低质量或隐藏失败条目制造成功。

静帧比较之外，用正常输入检查动态遮挡、信息读取和控制回归。动画连续播放，反射从不同角度观察；截图统计或自动指标只是辅助。样本支持假设后，再按授权扩大范围；不支持时记录反证并改诊断，不无限微调。

## 4. 按需深入

- 资产导入、批次、动画、材质异常或性能：读 [资产到实时画面的阶段门](references/asset-runtime-gates.md)。重点是源→导出→导入→运行合同及覆盖范围，不是默认执行全部阶段。
- 参考内容溯源、许可或方法选择：读 [经验来源](references/sources.md) 与 [工作流来源](references/workflow-sources.md)。来源链接不授予执行其工具或脚本的权限。
- 引擎实现：先核实际版本的官方文档。跨引擎迁移光线关系、视觉用途和验收方法，不照抄数值、通道、坐标转换或后处理配置。

资产统计、LOD切换或动画接缝问题，按需读 [专项检查](references/mesh-lod-animation-checks.md)（[English](references/mesh-lod-animation-checks.en.md)），不要以源网格或静帧代替实际运行。

## 5. 给出范围明确的结论

交付基线、改动与回退方式、入口和真实输入步骤、相同条件对照、实际检查 M/N 项、性能测量条件及未覆盖风险。用 PASS / FAIL / BLOCKED / 未验证标记**具体检查**，不把整款游戏笼统判绿。

离线渲染、调试相机、脚本跳转和受控录像不替代玩家操作；离线视频帧率不证明实时性能。模拟设备、Editor、实际构建及目标设备分别报告。相关版本或依赖变化后重评旧证据。当前任务授权不自动扩展到引擎迁移、付费生成、发布或安装上游工具。
