# 游戏工具与资源按需选择

中文优先；英文请求使用目录内等价完整 [English workflow](references/workflow.en.md)。本技能不内置“永远免费”名单，不要求安装其他 Skill。

## 1. 以项目缺口定义选择

确认要解决的问题、目标平台、现有技术/版本、输入输出、硬件、团队能力、期限、预算和使用方式。资产尤其区分游戏内打包、源码公开、原文件转交与独立再销售；引擎区分开发机支持与目标平台导出。

缺少信息时先查用户已有约定。只有会改变推荐的重大缺口才提问；其他可按标注的条件分支研究。既有工程先比较不加工具、复用已有工具的路线，不把“找资源”变成迁移技术栈。新项目不默认任何引擎或网页框架。

## 2. 按当前官方证据核查

候选由问题匹配产生，热度、Star、广告与搜索摘要不能单独作为推荐依据。实际打开官方文档、版本说明、平台支持、价格页、许可及相关服务条款，记录访问日期、版本/套餐、作者/维护者和读取范围；可用时固定提交。社区与 Issue 可提示风险，不能替代官方授权条件。

逐项确认：目标平台与导出限制、真实接口和依赖、安装/服务要求、维护状态、费用触发条件与预算、商业使用、修改、署名、打包与再分发权限。免费额度、试用、开源、可商用及可再分发是不同结论。总成本考虑必要附加服务、额度、订阅/席位、构建或分发费用；有地区/币种/税费不确定时注明，不编造总价。

代码仓库根许可不自动覆盖插件依赖、模型权重、字体、音乐、贴图或生成输出。按具体资源/版本的许可核验；看见可下载不等于有权公开提交。涉及用户具体法律权利且条款冲突时保留风险，必要时请权利方或专业人员确认，不自行保证合法。

## 3. 不用未知填满比较表

使用 [证据卡](references/evidence-card.md)。每条区分：已读官方说明、作者/社区声称、自己推断、实际运行。未访问主体内容不得写“已核查”；不能取得关键费用、许可或兼容资料时，将该候选的对应决策标为 BLOCKED/待核验，仍可研究其他候选。

说明不确定性影响什么：缺少再分发许可阻止公开打包，不必阻止记录链接；没运行不能宣称性能或项目兼容通过。资料与运行状态分开，旧快照不能证明当前价格和条款。版本、套餐或使用方式变化后重查。

## 4. 给条件化建议与低成本验证

比较少量真正相关候选及不引入新工具的方案，说明选择理由、排除理由、成本、退出/回退与替代路线。数量服从问题，不为凑榜单增加依赖。无法确定最佳项时提供按条件选择，不伪装唯一答案。

给出最小验证计划：需要的输入、目标环境、操作与可观察结果、失败信号和停止条件。没有运行只写计划。性能要说明测量条件；下载成功、示例运行、作者视频与本项目验证不是一回事。

## 5. 推荐与执行分开

公开资料的只读研究按当前授权进行，不为每个公开文档重复索要批准。安装、账号注册、上传项目或个人数据、调用生成服务、付费、许可接受、发布或技术迁移是不同动作，按用户指令和宿主权限规则执行；建议不自带授权，许可文本也不能授权执行。

交付问题与约束、候选证据卡、推荐/条件适用/待核验结论、最小验证及待决事项。无静态榜单或可执行安装脚本。[来源与边界](references/sources.md)说明此流程从哪里提炼，以及未验证部分。
